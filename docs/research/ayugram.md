# AyuGram: что умеет и что из этого полезно G2 AI Assistant

Исследование, октябрь 2026. Источники — README и исходники
[AyuGramDesktop](https://github.com/AyuGram/AyuGramDesktop) (ветка `dev`,
коммит `0f2a31b` от 20.10.2026, каталог `Telegram/SourceFiles/ayu/`),
README [AyuGram4A](https://github.com/AyuGram/AyuGram4A) и страница
[Ghost Mode](https://docs.ayugram.one/shared/ghost/) официальной документации.
Сайт `docs.ayugram.one` из окружения разработки недоступен, поэтому основной
источник — код: где описание и код расходятся, верить коду.

---

## Что это такое

AyuGram — **не расширение и не плагин**, а самостоятельный сторонний клиент
Telegram, то есть форк официального приложения со своими патчами. Входит в
аккаунт напрямую по номеру телефона, как Telegram Desktop.

| | Desktop | Android (AyuGram4A) |
|---|---|---|
| Основа | форк `telegramdesktop/tdesktop` (C++/Qt), заимствования из Kotatogram, 64Gram, Forkgram | форк exteraGram + патчи Telegraher, Cherrygram, Nagram |
| Лицензия | GPL-3.0 | GPL-2.0 |
| Платформы | Windows, macOS, Linux (AUR, nixpkgs, RPM Fusion, Flatpak, ALT, Gentoo, Void) | APK из канала `t.me/ayugram1338` |
| Исходники | открыты полностью | открыты **не полностью**: `AyuMessageUtils` и `AyuHistoryHook` — ядро сохранения истории — при сборке нужно писать самому |
| Разработчик | Radolyn | Radolyn |

Сам репозиторий Android-версии описывает себя как клиент «with ToS breaking
features in mind». Это стоит держать в голове при чтении всего, что ниже.

## Функции

### 1. Режим призрака (Ghost Mode)

Главная функция. В коде это класс `GhostModeAccountSettings`
(`ayu/ayu_settings.h`); настройки хранятся **на каждый аккаунт отдельно** либо,
при `useGlobalGhostMode`, общие для всех.

| Настройка в коде | В интерфейсе | Что делает |
|---|---|---|
| `sendReadMessages = false` | Don't Read Messages | Не отправляет отметку «прочитано». Голосовые и кружки тоже остаются непрочитанными |
| `sendReadStories = false` | Don't Read Stories | Просмотр историй не попадает в список просмотревших |
| `sendOnlinePackets = false` | Don't Send Online | Клиент не выходит в онлайн при открытии. Отправка сообщения всё равно переводит в онлайн — это ограничение сервера |
| `sendUploadProgress = false` | Don't Send Upload Progress | Нет «печатает…», «выбирает стикер», «отправляет фото» |
| `sendOfflinePacketAfterOnline` | Go Offline Automatically | Сразу после вынужденного онлайна шлёт «офлайн» |
| `markReadAfterAction` | Read on Interact | Помечает чат прочитанным, когда вы в нём что-то сделали (ответили, поставили реакцию) — чтобы призрак не бросался в глаза |
| `useScheduledMessages` | Schedule Messages | Отправляет сообщения как **отложенные** на несколько секунд вперёд — так они уходят без появления в онлайне. Задержка: `12 + max(6, ⌈0.7 × МБ вложений⌉) + 1` секунд (`getScheduleTime`), то есть от 19 с для текста |
| `sendWithoutSound` | Send without sound | Беззвучная отправка: никогда / только в режиме призрака / всегда |
| `suggestGhostModeBeforeViewingStory` | — | Предлагает включить призрака перед открытием истории |
| `*Locked` | — | Фиксирует отдельные пункты, чтобы общий переключатель их не трогал |

Переключатель режима выносится в боковое меню и в трей. Отдельные действия в
меню: «Прочитать до сюда» (`AddReadUntilAction`) и пометка прочитанным всего
списка чатов или ветки — то есть читать выборочно, оставаясь призраком.

### 2. История сообщений и защита от удаления (anti-recall)

Локальная база SQLite `tdata/ayudata.db` (`ayu/data/ayu_database.cpp`), таблицы:

| Таблица | Что хранит |
|---|---|
| `DeletedMessage` | Удалённые сообщения целиком: текст с разметкой, отправитель, пересылка, ответ, медиа (путь к файлу, миниатюра, сериализованный документ) |
| `EditedMessage` | Каждую предыдущую версию отредактированного сообщения |
| `DeletedDialog` | Удалённые диалоги и чаты, из которых вас выгнали |
| `RegexFilter`, `RegexFilterGlobalExclusion` | Фильтры (см. ниже) |
| `SpyMessageRead`, `SpyMessageContentsRead` | Когда собеседник прочитал ваше сообщение и когда открыл голосовое или медиа |

Как это выглядит:

- Удалённое собеседником сообщение **остаётся в чате** с меткой (по умолчанию
  значок вместо текста, текстовая метка — «🧹», настраивается), можно сделать
  его полупрозрачным.
- У отредактированного — метка и пункт меню «История правок» со всеми версиями.
- «Показать удалённые» в меню чата открывает отдельную ленту удалённых с
  поиском; их можно очистить по чату.
- Боты по умолчанию исключены (`saveForBots`).
- Одноразовые (TTL) фото и видео не сгорают при просмотре: для входящих есть
  пункт «Истечь» (`AddBurnAction`), который вручную отправляет
  `messages.readMessageContents`.
- На Android AyuSync синхронизирует историю и состояние прочтения между
  устройствами, через официальный сервер или свой
  ([AyuSyncBackend](https://github.com/AyuGram/AyuSyncBackend)).

Сохраняется только то, что клиент успел **получить**, пока был запущен.
Сообщение, удалённое до синхронизации, AyuGram не восстановит.

### 3. Фильтры сообщений

- Регулярные выражения: глобальные или на конкретный чат, с флагами
  «инвертировать» и «без учёта регистра», исключениями чатов; импорт и экспорт
  в JSON.
- «Теневой бан» (`shadowBanIds`): сообщения пользователя скрываются у вас,
  при этом он ничего не замечает.
- Скрытие сообщений от заблокированных, скрытие отдельного сообщения из меню,
  фильтр zalgo-текста.

### 4. Убрать лишнее

Отключение рекламы в каналах, историй, похожих каналов, кастомных фонов,
премиум-статусов, приветственного стикера; скрытие счётчиков уведомлений, папки
«Все чаты», реакций (отдельно для каналов, групп и личек), кнопки быстрого
шаринга. Настраиваемый состав бокового меню, кнопок поля ввода и контекстного
меню.

### 5. Локальный Premium

`localPremium` включает клиентские функции Premium без подписки: например,
отображение премиум-эмодзи у себя. Всё, что требует сервера, — отправка
премиум-эмодзи, расшифровка голосовых, увеличенные лимиты — без подписки не
работает. Включается только на вашем устройстве, другие пользователи ничего не
видят.

### 6. Удобства для опытных пользователей

- ID пользователя и чата в профиле (в формате Telegram API или Bot API),
  поиск пользователя по ID, дата регистрации аккаунта.
- «Подробности сообщения»: дата-центр, размер и MIME-тип файла, разрешение,
  точное время отправки и правки, автор стикерпака.
- Секунды во времени сообщений.
- «Повторить сообщение», «Все сообщения пользователя в чате», «Удалить все мои
  сообщения в чате», «Перейти к началу чата».
- Пересылка из чатов с запретом копирования (`AyuForward`): клиент скачивает
  медиа и отправляет заново, с прогрессом и отменой.
- «Скриншот сообщения» (Message Shot): картинка с выбранными сообщениями в
  выбранной теме.
- Быстрые админ-действия, подтверждения перед отправкой стикера, GIF, голосового
  и кружка.
- Переводчик: Telegram, Google, Yandex или системный.
- Подмена WebView под Android и увеличенное окно для мини-приложений.

### 7. Режим стримера

Окно AyuGram скрывается от захвата экрана: при трансляции или записи его не
видно. Есть реализации для Windows, macOS и Linux
(`features/streamer_mode/platform/`).

### 8. Внешний вид

Шрифты (основной и моноширинный), радиус пузырей и аватаров, хвосты сообщений,
Material-переключатели, иконка приложения, ширина колонки чата, адаптивный цвет
обложки трека. На macOS — предпросмотр медиа и быстрая реакция по force click.

## Риски

- **Условия Telegram.** Позиция авторов такая: условия для разработчиков API
  касаются разработчиков, а не пользователей, поэтому банить за клиент не за
  что. Это мнение авторов, а не позиция Telegram. Чтение без отметки,
  сохранение удалённого и копирование из защищённых чатов прямо обходят
  намерения собеседника, и ответственность за блокировку авторы с себя снимают.
- **Сохранённые чужие удалённые сообщения** лежат на диске в открытом SQLite.
  Это персональные данные третьих лиц, которые они пытались удалить.
- **Android.** Сборка не полностью открыта, используется Crashlytics
  (отключается в настройках).
- **macOS.** Cask в Homebrew помечен устаревшим из-за непрохождения проверки
  Gatekeeper.

## Что это значит для G2 AI Assistant

Сейчас README прямо говорит: «Отвечать на сообщения из других мессенджеров
нельзя — Even Hub SDK не даёт доступа к уведомлениям телефона». AyuGram эту
стену не убирает: это отдельный клиент, у него **нет API**, через который наш
сервер мог бы получать сообщения. Интегрироваться «с AyuGram» нельзя —
интегрироваться можно только с Telegram.

Реальный путь — тот же, по которому устроен сам AyuGram: сервер становится
собственным клиентом Telegram через MTProto (TDLib, GramJS для Node или
Telethon), с `api_id` и `api_hash` из my.telegram.org и входом по номеру
пользователя. Тогда идеи AyuGram переносятся естественно:

| Идея AyuGram | Как это выглядело бы на очках | Оценка |
|---|---|---|
| Чтение без отметки «прочитано» | «Что мне написали?» — сводка непрочитанного на HUD, отметки ставятся только по явной команде | **Полезно и уместно.** Глянуть на очки — не то же самое, что прочитать; не трогать `messages.readHistory` автоматически — нормальное поведение |
| Не светиться онлайн | Серверный клиент не шлёт `account.updateStatus`, иначе пользователь «онлайн» сутками | **Обязательно.** Иначе фоновый сервер сломает пользователю статус |
| Фильтры по regex и теневой бан | Какие чаты вообще пускать на HUD, что пропускать | **Полезно.** На маленьком дисплее фильтрация важнее, чем на телефоне |
| Отложенная отправка | Ответ голосом → `schedule_date` через N секунд, с окном «отменить» | Можно, но польза — в возможности отменить, а не в скрытности |
| История правок и удалённое | — | **Не делать.** Хранить чужие удалённые сообщения — против замысла собеседника и против принципа README «в базе остаются извлечённые поля, а не тело» |
| Пересылка из защищённых чатов, скриншоты, локальный Premium, стример-режим | — | Не относится к очкам |

Если двигаться в эту сторону, стоит учитывать:

1. **Сессия Telegram — это полный доступ к аккаунту.** Её строку нужно хранить
   так же, как ключ Anthropic: AES-256-GCM, никогда не возвращать в API. Отзыв
   — через «Unpair» и `auth.resetAuthorizations` для этой сессии.
2. **Вход** — номер, код, при необходимости пароль 2FA; всё это вводится на
   панели телефона, на очки не попадает.
3. **Свои `api_id` и `api_hash`**, а не официальные ключи клиента, как у
   AyuGram4A. Подмена под официальное приложение — прямой путь к блокировке.
4. **Ответы с очков** — отдельное решение. Сейчас помощник принципиально ничего
   не отправляет от имени пользователя (Gmail только на чтение). Отправка в
   Telegram — первая запись наружу, ей нужно явное подтверждение на HUD.

Предлагаемый первый шаг — **только чтение**: инструмент агента
`telegram_unread` (сводка непрочитанного без отметок о прочтении) и
уведомления на HUD из выбранных чатов. Это укладывается в текущую архитектуру:
`apps/server` получает ещё один источник наряду с Gmail, `packages/shared` —
тип карточки уведомления.
